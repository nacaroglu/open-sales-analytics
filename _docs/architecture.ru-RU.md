Open Sales Analytics — приложение React/Vite с единым origin, которое обслуживается FastAPI. Frontend хранит
идентификатор набора данных и bearer-токен в `sessionStorage` одной вкладки браузера; он отправляет выбранные диапазон
дат и сравнение в backend и отображает агрегированные ответы. Backend не хранит состояние между запросами, кроме
одного файла DuckDB на набор данных и ограниченного локального для процесса кеша ответов.

## Области репозитория

| Область | Фактический путь | Ответственность |
| --- | --- | --- |
| API и жизненный цикл | `backend/app/api/`, `backend/app/auth.py`, `backend/app/cleanup.py` | Загрузка/создание примера, авторизация, истечение срока, метаданные и оболочки ответов |
| Обзор | `backend/app/analytics/overview/` | Валовые продажи, уникальные заказы, единицы товара, средняя стоимость заказа, тренды и сравнения |
| Товары | `backend/app/analytics/products/` | Рейтинги, доля/Парето, рост, неактивность, история цен, проникновение и совместные покупки |
| Клиенты | `backend/app/analytics/customers/` | Покрытие, агрегаты клиентов, когорты, RFM и прогноз |
| Общие периоды и доступность | `backend/app/analytics/shared/` | Включительные фильтры дат, периоды сравнения, выбор интервала, доступность и определения метрик |
| Импорт и хранение | `backend/app/ingest.py`, `backend/app/importer.py`, `backend/app/schema.py` | Проверка CSV, построение фактов, запись файла набора данных и удаление промежуточных данных |
| Веб-интерфейс | `frontend/src/` | Загрузка, навигация панели, доступные состояния, таблицы и текстовые альтернативы диаграмм |

Авторитетные формулы и состояния метрик находятся в `backend/app/analytics/shared/metrics.py`; понятный человеку
каталог — в [_docs/metrics.ru-RU.md](metrics.ru-RU.md). Спецификация продукта Phase 3 находится в
[_docs/open_sales_analytics_phase_3_spec.md](open_sales_analytics_phase_3_spec.md).

## Файл набора данных

Каждая загрузка превращается в один приватный файл DuckDB в `DATASET_DIR`. При импорте переиспользуемые факты
вычисляются один раз; запросы во время работы фильтруют их по выбранному включительному диапазону и периоду сравнения.

| Таблица | Столбцы | Значение |
| --- | --- | --- |
| `line_items` | `order_id`, `order_date`, `product_id`, `product_name`, `quantity`, `unit_price`, nullable `customer_id` | Проверенные исходные строки; одна строка на товарную позицию, с необязательным непрозрачным ID клиента |
| `order_facts` | `order_id`, `first_order_date`, `last_order_date`, `line_count`, `units`, `gross_sales` | Одна строка на заказ и его итоговые показатели за весь срок |
| `product_facts` | `product_id`, `product_name`, `first_sale_date`, `last_sale_date`, `lifetime_gross_sales`, `lifetime_units`, `lifetime_orders` | Одна строка на товар и показатели портфеля за весь срок |
| `customer_facts` | `customer_id`, `first_order_date`, `acquisition_month`, `first_day_orders`, `last_order_date`, `lifetime_orders`, `lifetime_units`, `lifetime_gross_sales` | Одна строка на идентифицированного клиента; отсутствует или пуста для данных из шести столбцов |
| `dataset_meta` | `id`, `currency`, `created_at`, `expires_at`, `token_hash`, `row_count`, `has_customer_id`, `identified_orders`, `unidentified_orders`, `total_orders` | Идентификатор набора данных, жизненный цикл, безопасная для конфиденциальности проверка токена и счетчики покрытия |

Необработанные байты загрузки помещаются во временное хранилище только на время проверки/импорта и удаляются после
завершения импорта. Производные таблицы удаляются вместе с набором данных. Факты клиентов содержат только
псевдонимные ID и никогда не возвращаются в виде списка клиентов.

## Поток запросов

1. `POST /api/datasets` проверяет multipart CSV, применяет правила строк и связей между строками, создает факты DuckDB,
   сохраняет только SHA-256-хеш токена и возвращает ID набора данных, одноразовый токен, метаданные и исходный обзор.
2. `require_dataset` проверяет bearer-заголовок, ID набора данных, читаемость файла, срок действия и токен до запуска
   обработчика модуля. Авторизация выполняется перед каждым запросом, в том числе при попадании в кеш.
3. Обработчик определяет включительный активный диапазон и режим сравнения, строит ключ кеша и либо возвращает успешно
   закешированное тело JSON, либо открывает набор данных только для чтения и вычисляет ответ модуля.
4. Ответ представляет собой только агрегированный JSON. В кеше хранятся лишь успешно сериализованные тела с ключом,
   включающим ID набора данных, модуль, активные даты, режим сравнения и параметры модуля.
5. Истечение срока набора данных, явное удаление и проход очистки аннулируют его записи кеша. Кеш локален для процесса,
   потокобезопасен, ограничен алгоритмом LRU и удаляет записи в более ранний из моментов: по своему TTL или по сроку
   набора данных.

## Поверхность API

Все маршруты наборов данных требуют `Authorization: Bearer <token>`, кроме общедоступных маршрутов проверки состояния,
конфигурации и скачивания примера. Авторитетным является актуальная схема OpenAPI; соответствие этой таблицы схеме
проверяет `backend/tests/test_documentation.py`.

| Метод | Путь | Авторизация | Назначение и основные параметры |
| --- | --- | --- | --- |
| GET | `/api/health` | Нет | Проверка работоспособности |
| GET | `/api/config` | Нет | Флаг общедоступного демо и ограничения загрузки; никаких секретов или путей |
| POST | `/api/datasets` | Нет | Multipart-загрузка; поле формы `currency` |
| POST | `/api/datasets/sample` | Нет | Импорт встроенного примера в USD |
| GET | `/api/sample.csv` | Нет | Скачать встроенный пример CSV |
| GET | `/api/datasets/{id}` | Да | Метаданные набора данных, возможности, покрытие и срок действия |
| GET | `/api/datasets/{id}/analytics` | Да | Устаревшая сводка обзора; необязательные `start`, `end` |
| DELETE | `/api/datasets/{id}` | Да | Удалить набор данных и аннулировать его кеш |
| GET | `/api/datasets/{id}/overview` | Да | KPI обзора и тренд; `start`, `end`, `comparison` |
| GET | `/api/datasets/{id}/products` | Да | Аналитика портфеля; `start`, `end`, `comparison`, `dormancy_days` |
| GET | `/api/datasets/{id}/products/detail` | Да | Детали товара; `product_id`, `start`, `end`, `comparison` |
| GET | `/api/datasets/{id}/customers` | Да | Агрегаты клиентов и прогноз; `start`, `end`, `comparison` |

## Схема развертывания

Образ Docker собирает frontend на этапе Node, устанавливает окружение backend с помощью `uv` и запускает один процесс
FastAPI. FastAPI обслуживает собранное SPA и `/api` на порту 8000. Если наборы данных должны переживать перезапуск,
`DATASET_DIR` следует разместить в приватном постоянном томе; общей базы данных и слоя горизонтального масштабирования нет.
